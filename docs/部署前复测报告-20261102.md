# 南开校园安全卫士部署前复测报告

复测日期：2026-11-02

复测依据：用户提供的《南开校园安全卫士测试验收清单》及当前项目代码、MySQL 数据与飞书入口实际情况。

## 一 结论

当前本地 Node.js + MySQL 版本已通过自动化完整性检查和主要接口复测，可继续进入人工验收阶段。消防主题展示所需的 10 道消防答题、10 个情景及前三个不同消防情景已就绪。

正式飞书端尚不能直接判定部署通过：现有飞书“安全知识”入口指向 GitHub Pages 静态地址，无法连接本项目的 Node.js/MySQL 后端。需要部署公网 HTTPS 后端并更新飞书菜单地址后，再做最终验收。

## 二 测试结果中发现的问题及处理

| 测试问题 | 原因 | 本轮处理 | 当前状态 |
|---|---|---|---|
| 消防情景排序为 1、2、4 | 情景排序依赖原数据顺序 | 增加明确排序规则，前三位固定为不同消防主题 | 已修复 |
| 情景总量不足 10 个 | 静态已发布案例不足 | 补充两个完整消防案例并同步 MySQL | 已修复 |
| 飞书入口看不到学习任务 | GitHub Pages 无后端；首次登录资料为空也会被范围过滤 | 增加静态演示兜底，并修复后端任务资格判断 | 本地已修复；正式飞书端待部署 |
| 三角色选项装饰错位 | 伪元素和绝对定位在不同尺寸下重叠 | 改为稳定网格布局并关闭多余装饰 | 已修复，待大屏人工确认 |
| 右上角出现白色框 | 封面装饰占位元素仍显示 | 明确隐藏该装饰元素 | 已修复 |
| 启动后未自动打开页面 | 自检先于打开浏览器，警告中断后续动作 | 调整启动次序并增加 MySQL 健康检查 | 已修复 |
| 管理员可隐式访问其他角色接口 | 旧权限逻辑将管理员视作超级角色 | 改为严格按已授角色判断 | 已修复 |
| 案例状态可能被越级修改 | 状态流转和完整性校验不足 | 限制合法流转、完整性检查、退回原因必填 | 已修复 |

## 六 部署建议

1. 将 Node.js 服务和 MySQL 部署到可被飞书访问的 HTTPS 地址。
2. 正式环境启用飞书登录校验，配置正确 OAuth 回调地址。
3. 将飞书“安全知识”菜单由 GitHub Pages 改为正式后端地址，并重新发布配置。
4. 更换 MySQL 密码和会话密钥，不要把 `.env` 上传到公开仓库。
5. 导入 `database/nankai_security_guard_full.sql` 后执行 `npm run predeploy`。
6. 人工验收全部通过后，再开放给正式用户。
