# 南开校园安全卫士测试验收清单

版本日期：2026-10-27  
测试目标：确认消防活动演示链路、四角色权限、学习任务和后台内容流程可正常使用。

## 一、测试前准备

1. 使用项目最新版，双击 `启动-消防活动演示版.bat`，等待浏览器打开。
2. 学生端地址：<http://localhost:8021/knowledge.html>
3. 一键求助地址：<http://localhost:8021/help.html>
4. 后台角色从学生端顶部“切换角色”进入，不需要复制登录链接。
5. 准备管理员、编辑员、审核员各一个有效测试账号。账号由项目负责人单独提供，测试记录中不要填写密码。
6. 飞书功能测试时使用已发布的“南开校园安全卫士”机器人，并确认电脑能正常访问南开 NK-GeniOS、飞书及本地网页。
7. 建议浏览器：最新版 Edge 或 Chrome。至少测试一次电脑端 1920×1080 和活动现场 78 英寸触屏的实际分辨率。

当前内容基线：

- 题库共 315 题，其中消防安全题 50 题。
- 日常消防答题每轮展示 10 题。
- 当前运行页面应展示 10 个情景，排序第 1、2、3 的情景均应为消防主题。
- 每个情景均可选择体验者、帮助者、观察者三种身份。

## 三、学生端详细测试（P1）

### 1. 页面与角色入口

- 刷新学生端，顶部品牌、学生学习和切换角色按钮应完整显示。
- 打开角色菜单后，菜单不能被页面内容遮挡。
- 点击菜单外或选择角色后能够正常离开菜单。
- 浏览器缩小到手机宽度时，四个角色入口仍可阅读和点击，没有横向溢出。
- 从后台登录页点击“学生”，应返回知识学习页面。

### 2. 学习任务

- 未登录或没有匹配任务时，应显示明确提示，不能一直停留在“正在读取”。
- 有匹配任务时，应显示任务名称、适用范围、题数、合格线、截止时间和学习主题。
- 题目未作答时，不能直接进入下一题或应给出明确提示。
- 作答后应显示正确/错误反馈，分数变化正确。
- 完成任务后应生成一条学习记录；重复刷新不能生成重复记录。
- 已结束、未开始、已停用的任务不应作为可正常完成的当前任务出现。

### 3. 日常消防答题

- 每轮应抽取 10 道题，题干、四个选项、答案和解析均完整。
- 连续刷新或开始新一轮，题目允许随机变化，但不能出现空题或重复按钮失效。
- 测试全对、全错和部分正确三种情况，最终得分应与实际作答一致。
- 快速连续点击“下一题”不能跳题、重复计分或导致页面卡死。

### 4. 情景演练

- 左右切换按钮、底部情景圆点和“进入演练”按钮均可使用。
- 第 1、2、3 个消防情景应是三个不同场景，内容之间不能只是改标题。
- 每个消防情景分别测试体验者、帮助者、观察者，共 9 条完整路径。
- 每个角色的题目应符合其视角，选项选择后剧情衔接合理。
- 中途按浏览器返回、刷新页面、切换标签，系统不能出现永久锁死；应能重新进入或给出提示。
- 到达结局后应展示结局说明、风险信号和安全动作，并可返回情景列表。
- 情景封面不能再出现无意义的右上角白色占位框，消防主题应有一致的消防视觉元素。

### 5. 一键求助

- 页面应清楚显示保卫处值班电话和使用说明。
- 手机端点击拨号按钮可调起电话；电脑端不能出现无法关闭的错误弹窗。
- 紧急提示文字应清晰可见，不能被悬浮按钮遮挡。

## 四、后台与权限测试（P1）

### 1. 登录和权限

- 三个后台登录页顶部应显示学生、管理员、编辑员、审核员切换栏，当前角色高亮。
- 空账号、空密码、错误账号和错误密码均应给出明确错误提示。
- 管理员账号不能以编辑员或审核员角色错误进入，其他角色同理。
- 未登录时直接访问 `/admin.html`、`/editor.html`、`/reviewer.html`，应跳转登录页。
- 点击退出后应回到相应登录页；浏览器返回不能继续操作已退出的后台。
- 停用账号不能登录。

### 2. 管理员

- 学习任务：新建、发布、停用、重新启用、删除均能生效。
- 新建任务缺少适用年级或学习主题时，应阻止发布并提示具体原因。
- 题目数量只能设置为 5–30，合格分数只能设置为 0–100。
- 开始时间晚于截止时间时，应阻止发布或明确提示。
- 学习统计应按所选任务切换，完成人数、平均分、主题掌握情况和高频错题数据一致。
- 题库管理应显示题目总数和分类数量；上传合法题库后可解析，重复题应跳过。
- 上传错误格式、空文件或缺少必要字段的文件，应提示失败，原题库不能被破坏。
- 题库版本记录可以查看和下载。
- 角色管理可以新增、编辑、启用、停用管理员/编辑员/审核员，并可修改密码。

### 3. 编辑员

- “待完善”“退回修改”“已提交审核”三个列表切换正常。
- 打开案例后能看到来源名称、原文内容、原文链接和发布时间。
- 原文链接应进入对应的权威来源页面。
- 未完成必填项或风险信号/安全动作不足时，应阻止提交并指出缺失内容。
- 保存并提交后，案例从编辑列表转入审核员的“待审核”。
- 弃用案例需要二次确认；弃用后不再出现在学生端和待审核列表。

### 4. 审核员

- “待审核”和“已发布”列表切换、搜索和分类筛选正常。
- 审核通过后，案例状态变为已发布，并能在学生端情景列表看到。
- 退回时必须填写清楚原因；退回后案例出现在编辑员“退回修改”。
- 已发布案例执行撤回后，应从学生端消失并回到编辑修改流程。
- 刷新页面后状态不能恢复成操作前状态。

### 5. 完整业务闭环

请用一条专门的测试案例完成以下流程，并记录每一步截图：

`编辑员保存并提交 → 审核员退回 → 编辑员修改并再次提交 → 审核员通过发布 → 学生端出现 → 审核员撤回 → 学生端消失`

## 五、飞书与网络测试（P1）

- 机器人能回答消防、反诈、实验室安全、一键求助等常见问题。
- 回答中涉及紧急危险时，应优先提示确保人身安全、联系现场工作人员或拨打应急电话。
- 连续发送短消息、表情和不完整问题，机器人不能一直无响应。
- “隐患上报”表单可填写类型、地点、描述、紧急程度、图片和联系方式并成功提交。
- 飞书登录后能返回原来选择的学生、编辑员或审核员页面。
- OAuth 回调链接重复打开时应给出可理解的失败提示，并能从正常入口重新登录。
- 校园网、非校园网、开启 VPN、关闭 VPN 四种网络状态分别记录结果，区分“项目故障”和“网络无法访问”。
- 飞书管理群的待编辑、待审核提醒只在有待办时发送，链接进入正确角色工作台。

## 六、兼容性与现场展示测试（P1）

- Edge 和 Chrome 各完成一遍 P0 流程。
- 电脑全屏、半屏、手机宽度和 78 英寸触屏分别检查排版。
- 所有主要按钮在触屏上容易点击，不能过小或靠得太近。
- 页面缩放 100%、125%、150% 时没有文字重叠、按钮被截断或横向滚动。
- 连续演示 30 分钟，重复切换答题、情景和后台页面，服务不应停止。
- 刷新、关闭后重新打开浏览器，已写入数据库的数据仍然存在。
- 断开数据库或停止后端时，页面应显示明确错误信息，不能无限加载。

## 七、消防活动现场重点验收顺序

建议测试同学按以下顺序完整录屏一次：

1. 飞书机器人询问一个消防问题。
2. 从飞书菜单进入安全知识。
3. 完成 2–3 道消防答题，展示即时反馈。
4. 进入第 1 个消防情景，选择一个角色走到结局。
5. 返回首页，通过顶部角色入口进入管理员登录页。
6. 管理员查看消防学习任务和学习统计。
7. 打开隐患上报和一键求助入口。

目标是整段流程在 3–5 分钟内完成，无白屏、无等待超时、无需要手工复制地址的步骤。

## 八、问题记录格式

发现问题时请按以下格式提交：

```text
问题标题：
严重程度：阻塞 / 严重 / 一般 / 建议
测试角色：学生 / 管理员 / 编辑员 / 审核员 / 飞书机器人
测试环境：电脑型号、Windows 版本、浏览器及版本、是否校园网、是否开启 VPN
前置条件：
复现步骤：1.  2.  3.
实际结果：
预期结果：
发生时间：
截图或录屏：
是否稳定复现：每次 / 偶发 / 仅一次
```

严重程度说明：

- **阻塞**：项目无法启动、无法登录、页面白屏、核心演示链路无法继续。
- **严重**：成绩或案例状态错误、角色越权、发布后学生端不可见、数据丢失。
- **一般**：某个按钮或提示异常，但可通过其他方式继续测试。
- **建议**：文字、排版、颜色、动效等体验优化。
