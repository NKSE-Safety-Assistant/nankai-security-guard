## 一 项目现状

当前版本已经形成一套可在本地运行的校园安全学习与管理系统，包含学生知识学习、消防专题答题、三角色情景演练、学习任务、学习统计、编辑审核流程、后台角色管理、一键求助以及飞书机器人入口。项目支持 JSON 本地演示和 MySQL 完整运行两种模式。

本次交接包包含当前源代码、网页资源、Node.js 后端、JSON 数据、MySQL 完整 SQL 备份、数据库导入脚本、启动脚本、测试验收清单、消防活动展示材料和项目说明文档。接收人员在安装 Node.js 18 或更高版本后，可以优先使用本地 JSON 版检查页面，也可以导入 MySQL 备份还原完整数据。

## 三 系统角色和页面入口

| 角色 | 页面入口 | 主要功能 |
|---|---|---|
| 学生 | `http://localhost:8021/knowledge.html` | 学习任务、消防答题、三角色情景演练 |
| 管理员 | 学生端顶部切换角色，或 `/admin-login.html?role=admin&next=%2Fadmin.html` | 任务、统计、题库和角色管理 |
| 编辑员 | 学生端顶部切换角色，或 `/admin-login.html?role=editor&next=%2Feditor.html` | 整理案例、脱敏、提交审核 |
| 审核员 | 学生端顶部切换角色，或 `/admin-login.html?role=reviewer&next=%2Freviewer.html` | 审核、发布、退回和撤回案例 |
| 一键求助 | `http://localhost:8021/help.html` | 显示值班电话和求助说明 |

后台三个角色共用 `admin-login.html`。角色与受保护页面的映射在 `server.js` 中配置，静态页面环境的访问控制由 `static-auth-guard.js` 辅助处理。

## 五 启动方法

### 1 消防活动演示

1. 安装 Node.js 18 或更高版本。
2. 解压完整交接包。
3. 双击 `启动-消防活动演示版.bat`。
4. 浏览器访问 `http://localhost:8021/knowledge.html`。
5. 演示前双击 `活动演示自检.bat`，全部显示通过后再进行现场展示。

### 2 本地 JSON 版

双击 `启动-本地JSON版.bat`。该方式不要求安装或启动 MySQL，适合页面检查、离线演示和开发调试。

### 3 MySQL 完整版

1. 安装 MySQL 8.0 和 Node.js 18 或更高版本。
2. 双击 `导入-MySQL数据库.bat`，按提示输入 MySQL 账号、密码和数据库名。
3. 检查 `.env` 中的 MySQL 地址、端口、账号、密码和数据库名。
4. 在项目目录执行 `npm start`，或使用现有启动脚本。
5. 打开学生端，通过顶部角色入口进入不同角色页面。

## 六 配置与账号说明

- 当前 `.env` 用于这台电脑的 MySQL 演示环境，包含本机数据库连接口令和会话密钥。交接包只能交给项目授权人员，不应上传公开网盘或公共代码仓库。
- 飞书 App ID、App Secret 和 Webhook 在交接包中没有完整配置。迁移到新服务器后，需要由飞书应用管理员重新填写。
- 本地演示可将 `FEISHU_AUTH_REQUIRED` 设为 `false`。正式接入飞书登录时应设为 `true`，并正确配置公网地址和 OAuth 回调地址。
- 后台账号由管理员页面的“角色授权管理”维护。交接时应通过安全渠道单独传递密码，不能将密码写进公开测试报告。
- 正式部署前应更换 MySQL 密码和 `SESSION_SECRET`，并限制数据库和交接包的访问范围。

## 七 核心业务流程

### 1 学习任务

管理员创建并发布任务，学生端读取符合年级和主题条件的有效任务。学生完成答题后，系统保存总分、题目明细和完成时间，管理员在学习统计页查看完成率、平均分和最近完成记录。

### 2 案例编辑审核

案例状态按照以下流程流转：

`待完善 → 待审核 → 已发布`

`待审核 → 退回修改 → 待审核`

`已发布 → 撤回 → 退回修改`

只有已发布案例会进入学生端情景学习。编辑员负责整理、脱敏和提交，审核员负责核验、退回、发布和撤回。

### 3 飞书服务

飞书机器人提供安全咨询、隐患上报、一键求助和安全知识入口。飞书登录、群通知和 OAuth 回调依赖可访问的 NK-GeniOS、飞书网络和正确的应用配置。如果开启 VPN 后无法访问校内服务，应分别测试校园网、非校园网、开启 VPN 和关闭 VPN，区分网络问题与项目问题。

## 十 已知限制和后续工作

- 本地地址只能供本机使用。其他电脑或手机访问时，需要部署到可访问服务器，或配置同一局域网地址和防火墙规则。
- 飞书 OAuth 不能使用纯静态 GitHub Pages 完成，需要运行 Node.js 后端并配置正确的回调地址。
- 校内 NK-GeniOS 与外部网络工具可能存在 VPN 路由冲突，现场应提前确定可同时满足飞书和展示网页访问的网络方案。
- 现场展示前建议关闭无关浏览器标签、固定浏览器缩放为 100%，并提前完成一遍 3 至 5 分钟的完整录屏演练。
- 正式上线前应完成账号口令更换、HTTPS、数据访问权限、日志轮换和数据库定期备份配置。

### 当前部署阻断项

测试截图中的飞书“安全知识”入口仍指向 GitHub Pages。GitHub Pages 只能托管静态页面，不能直接运行本项目的 Node.js 接口或连接 MySQL，因此只能显示静态演示任务，无法完成正式任务读取、成绩保存和后台统计。正式上线前必须先部署后端与 MySQL，再把飞书菜单地址改为该公网 HTTPS 地址；这项外部平台配置完成并验证前，不应判定正式飞书端部署验收通过。
