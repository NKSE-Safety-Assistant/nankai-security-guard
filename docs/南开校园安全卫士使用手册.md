# 南开校园安全卫士使用手册

本手册面向学生、编辑员和审核员。系统由飞书机器人、网页端、Node.js 后端和 MySQL 数据库组成：学生在飞书内获取安全服务和学习内容，编辑员与审核员通过独立工作台维护安全案例。

## 一、学生端

### 1. 从飞书进入

在飞书中打开“南开校园安全卫士”机器人。机器人首页为对话输入框，可直接咨询校园安全问题；底部菜单提供“隐患上报”“一键求助”“安全知识”三个入口。

![飞书机器人菜单](manual-screenshots/08-feishu-bot-menu.png)

机器人会优先检索已同步的校内制度、治安处理规定和官方安全信息，并尽量给出依据来源。遇到紧急情况或信息不完整时，应以保卫处、公安等官方渠道的最新指引为准。

![飞书机器人问答](manual-screenshots/07-feishu-bot-chat.png)

### 2. 隐患上报与一键求助

点击“隐患上报”进入飞书表单，按要求填写隐患类型、时间、地点、紧急程度、事实描述、图片附件和联系方式。提交后，信息进入飞书表单后台，供保卫处工作人员核验和处置。

点击“一键求助”进入求助页面。手机端可调起电话拨号；电脑端会显示保卫处值班电话，用户可自行拨打。该功能适用于突发风险、夜间求助或发现校园异常情况等场景。

![一键求助页面](manual-screenshots/01-help.png)

### 3. 安全知识学习

点击“安全知识”后，系统会通过飞书识别当前用户。该验证不限制学生访问，主要用于记录学习身份和学习完成情况。登录成功后，系统会将飞书用户 ID、飞书账号名称和最近访问时间写入学生信息表。

![飞书内嵌安全知识页面](manual-screenshots/05-feishu-knowledge-embedded.png)

安全知识页面包括两种学习方式：

1. **安全答题**：系统从题库中随机展示 10 道安全知识题，学生作答后可查看即时反馈。
2. **三角色学习模式**：学生从已发布案例中选择情景，并以体验者、帮助者或观察者身份推进故事。不同选择会进入不同分支和结局。

学生完成三角色学习并到达结局后，系统会在学习记录表中保存案例、所选角色、结局类型和完成时间。学生端只读取审核状态为“已发布”的案例。

![安全知识页面](manual-screenshots/02-knowledge.png)

## 二、编辑员工作台

编辑员负责将系统采集到的官方安全信息整理为可学习、可核验、可发布的校园安全案例。编辑员从飞书群消息链接或编辑员页面进入工作台，并通过飞书身份验证。

### 1. 案例从哪里来

系统每天 00:00 自动访问南开大学保卫处、网信办、实验室设备处及公安、消防等权威公开网站，提取安全相关页面。系统会保存来源名称、原文详情链接、发布时间和完整采集原文，并与数据库已有案例查重：来源链接相同或内容高度相似时不重复进入人工流程；新案例写入案例库，状态为“待完善”。编辑员也可在工作台手动执行一次采集。

### 2. 三类工作状态

- **待完善**：自动采集的新案例，等待首次整理。
- **退回修改**：审核员提出修改意见后的案例。
- **已提交**：已提交审核员的案例。该状态只读，编辑员可查看内容和处理进度；审核员退回后，案例会回到“退回修改”。

![编辑员工作台](manual-screenshots/03-editor.png)

### 3. 编辑步骤

1. 在左侧列表选择一条“待完善”或“退回修改”案例。
2. 展开“采集原文信息”，确认来源标题、完整原文内容和“打开原文核验链接”是否能直达官方详情页。
3. 点击“载入采集原文摘要”，将原文复制到“脱敏后案例材料”中；在该编辑框内删除或泛化姓名、学院或楼宇等具体地点、账号、电话、邮箱、金额、交易编号等敏感信息。
4. 选择安全类型和具体校园情景。若没有合适的校园情景，可选择“其他”并自行填写。
5. 补全案例标题、情景开端、风险升级、脱敏说明、风险信号和安全动作。风险信号与安全动作应每行一条，分别至少填写 3 条；安全动作要写清学生可以执行的做法和核验或求助对象。
6. 查看页面中的五项整理检查。全部满足后，点击“保存并提交给审核员”。系统会先保存正文，再将状态改为“待审核”，并向飞书案例管理群发送审核员待办提醒。

### 4. 弃用不适合的案例

如果案例虽然来自官方来源，但内容不适合改编为学生学习情景，例如信息过于笼统、无法还原风险过程或与校园场景关联较弱，编辑员可填写“编辑备注 / 弃用原因”，再点击“弃用该案例”。确认后，系统将案例状态写为“已弃用”。

已弃用案例保留在数据库中，用于追溯采集和处理记录，但不会进入审核流程、不会发布到学生端，也不会再次作为待编辑任务出现。

## 三、审核员工作台

审核员负责复核已提交案例并决定发布或退回。审核员通过飞书身份验证进入审核员工作台，可查看“待审核”和“已发布”两个模块。

![审核员工作台](manual-screenshots/04-reviewer.png)

### 1. 审核待审核案例

审核员打开案例后，重点检查以下内容：

1. 来源是否为学校或权威公开渠道，原文链接是否可直接打开。
2. 脱敏后案例材料是否删除或泛化了可识别个人信息。
3. 安全类型、校园情景、情景开端和风险升级是否准确、完整。
4. 风险信号是否具体，安全动作是否清晰且可执行。

五项检查均通过后，点击“审核通过并发布”。系统会将案例状态写为“已发布”，学生端即可读取该案例。

如需修改，在“审核意见 / 退回原因”中写明不符合要求的项目，再点击“退回编辑员修改”。案例将回到编辑员的“退回修改”列表，并向飞书案例管理群发送编辑员待办提醒。

### 2. 管理已发布案例

审核员可在“已发布”中按安全类型浏览，并搜索案例标题、来源、风险信号和安全动作。若已发布案例后续发现来源、表述或安全建议存在问题，可打开案例并点击“撤回并退回编辑员”，案例会从学生端移除，重新进入修改流程。

## 四、飞书案例管理群

案例管理群只用于待办提醒和进入工作台，不在群内直接编辑案例。

- 每天上午 9:00，系统仅在存在待办时发送提醒：编辑员收到“待编辑 X 条”，审核员收到“待审核 X 条”。
- 系统自动采集到新案例时，向群内发送编辑员待办提醒。
- 审核员退回案例时，向群内发送编辑员待办提醒。
- 消息附带编辑员或审核员页面链接。工作人员点击链接后，通过飞书验证进入对应工作台。

![飞书管理群待办提醒](manual-screenshots/06-feishu-todo-group.png)

## 五、数据库与状态流转

系统使用 MySQL 数据库保存案例、用户和学习记录。采集、保存、提交、退回、发布、撤回和弃用操作都会写回数据库。

`待完善` → `待审核` → `已发布`

`待审核` → `退回修改` → `待审核`

`待完善` / `退回修改` → `已弃用`

其中，只有“已发布”案例对学生端可见；“已弃用”案例仅保留后台追溯，不会进入审核和学习流程。

## 六、常见问题

### 1. 飞书登录后显示无法访问

请从机器人菜单、飞书群消息或以下页面重新进入：`knowledge.html`、`editor.html`、`reviewer.html`。不要反复打开带有 `/api/auth/callback?code=...` 的地址；该地址是一次性临时回调链接，过期后无法再次使用。

### 2. 页面提示数据库连接失败

检查 Node.js 后端是否已运行、MySQL 服务是否开启，以及项目 `.env` 文件中的数据库地址、账号、密码和数据库名称是否正确。正式部署时，Node.js 后端、MySQL、HTTPS 域名和飞书 OAuth 回调地址必须部署在同一套可访问的服务器环境中。

### 3. 为什么学生端看不到刚编辑的案例

案例需依次经过编辑员提交和审核员发布。只有状态为“已发布”的案例才会进入安全知识页面。
